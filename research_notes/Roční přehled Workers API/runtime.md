# Workers runtime, globals, modules, and execution APIs: annual compatibility research

## What was reviewed, and how should dates and compatibility claims be interpreted?

### Takeaway

The review covers **2025-10-05 through 2026-10-05 inclusive** and compares the actual Lopata PR #31 code at **`8b82801ac83d4880d64a0cfa948698347ea84f1a`**. The earlier compatibility document covers only April 2–October 2, 2026, so it omits relevant late-2025 and early-2026 changes. [PR code](https://github.com/contember/lopata/tree/8b82801ac83d4880d64a0cfa948698347ea84f1a); [existing review scope](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/CLOUDFLARE-COMPATIBILITY.md#L1-L16)

### Cited Findings

- **Scope:** globals/Web APIs, `cloudflare:*` modules, WorkerEntrypoint/RPC, Worker Loader/Dynamic Workers, Node.js compatibility, cryptography, WebSockets/streams, tracing, Access context identity, and TCP/gRPC. Lopata runs user code in Bun workers and implements Cloudflare modules and bindings in TypeScript; it does not run workerd. This matters when separating native Bun availability from Cloudflare semantics. [Architecture](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/CLAUDE.md#L24-L64)
- **Source coverage:** official Workers product changelog pages 1–7, the runtime changelog, compatibility flags, relevant API reference pages, and official Cloudflare launch articles. Product announcement dates, runtime release-entry dates, compatibility activation dates, and documentation modification dates are recorded separately below. [Product changelog](https://developers.cloudflare.com/changelog/?product=workers); [runtime changelog](https://developers.cloudflare.com/workers/platform/changelog/); [compatibility flags](https://developers.cloudflare.com/workers/configuration/compatibility-flags/)
- **Important date correction:** the modern WebCrypto announcement's URL contains `2026-09-28`, but the visible publication date is **October 1, 2026**. It belongs in the window, with October 1 as the announcement date. [Official announcement](https://developers.cloudflare.com/changelog/post/2026-09-28-webcrypto-modern-algorithms/)
- **Important date discrepancy:** the runtime changelog dates the 32 MiB WebSocket message limit to **October 25, 2025**; the dedicated announcement is **October 31, 2025**. Both are in the window. Do not silently substitute one date for the other. [Runtime changelog](https://developers.cloudflare.com/workers/platform/changelog/); [announcement](https://developers.cloudflare.com/changelog/post/2025-10-31-increased-websocket-message-size-limit/)
- **Important delayed announcement:** standard WebSocket `binaryType` behavior became default for compatibility dates **March 17, 2026** or later, but was announced **April 21, 2026**. The announcement explicitly acknowledges delayed documentation. [Announcement](https://developers.cloudflare.com/changelog/post/2026-04-21-websocket-standard-binary-type/); [compatibility flags](https://developers.cloudflare.com/workers/configuration/compatibility-flags/)
- **Pre-window introduction, in-window activation:** `ctx.exports` was announced **September 26, 2025**, outside the window. Its default activation on **November 17, 2025**, and later loopback extensions belong in the annual inventory. [Introduction](https://developers.cloudflare.com/changelog/post/2025-09-26-ctx-exports/); [compatibility flags](https://developers.cloudflare.com/workers/configuration/compatibility-flags/)
- **Do not use the feature matrix as implementation evidence:** `FEATURES.md` still says `ctx.exports` is missing and gives a 1 MiB WebSocket limit. Actual code creates WorkerEntrypoint loopbacks and preserves `Response`'s `webSocket` initializer. [Stale matrix](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/FEATURES.md#L120-L140); [loopback implementation](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings/worker-cache.ts#L627-L645); [Response shim](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/setup-globals.ts#L85-L96)

### Inferences

- Classifications in these notes mean: **missing** = absent callable contract; **partial** = relevant implementation exists but does not satisfy the documented contract; **native-supported** = the relevant Bun behavior was observed or source delegates to Bun, without claiming full workerd equivalence; **cloud-only** = hosted enforcement or real edge data cannot be reproduced by an intrinsic local API.
- Priority reflects local application compatibility and concrete breakage, not Cloudflare announcement prominence. The tracing, WebSocket, and Dynamic Worker gaps are particularly actionable because they affect code that developers can exercise locally.

### Gaps

- No live Cloudflare deployment or workerd conformance run was performed. Documentation and source comparison establish contracts and omissions, not complete runtime equivalence.
- Documentation modification dates do not establish initial availability. Features whose original release date was not found are marked explicitly rather than counted as new annual launches.
- The local workerd reference checkout was at `8ae9e49a59e9027056124673331116ab902f0608`, dated March 12, 2026. It was useful for older flag definitions, but cannot establish the absence of later APIs.

## Which tracing and observability contracts are missing after PR #31?

### Takeaway

PR #31 implements the original `enterSpan` shape, but omits the July and September API expansion. The gap is much broader than the deferred `getActiveSpan()` mentioned in the compatibility notes, and Vite's generated module does not export even the existing `tracing` namespace. [Span implementation](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/tracing/span.ts#L138-L150); [Vite module](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/vite-plugin/modules-plugin.ts#L44-L81); [documented API](https://developers.cloudflare.com/workers/observability/traces/custom-spans/)

### Cited Findings

- **June 16, 2026 — initial custom spans:** Cloudflare introduced `tracing.enterSpan` through both `import { tracing } from 'cloudflare:workers'` and `ctx.tracing`. Lopata provides the imported namespace through the Bun virtual module and `ctx.tracing` through the in-process execution context only. The normal Worker-thread context lacks `ctx.tracing`, and Vite's generated module lacks the named `tracing` export; see the [reconciled backend distinction in the report](../../reports/Roční%20přehled%20Workers%20API.md#tracing-coverage-is-smaller-than-the-public-namespace-suggests). The existing span implementation preserves synchronous callback returns, ends on promise settlement, and records thrown errors. **Classification: supported basic implementation, partial backend wiring; confidence high.** [Announcement](https://developers.cloudflare.com/changelog/post/2026-06-16-custom-spans/); [virtual module, lines 44–52](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/virtual-modules.ts#L44-L52); [context, lines 24–34](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/execution-context.ts#L24-L34); [span runner](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/tracing/span.ts#L36-L117)
- **July 28, 2026 — `startActiveSpan` and manual completion:** the new method makes the span active inside its callback without automatically ending it. `Span.end()` supports streams or work that outlives the callback. Lopata exports only `{ enterSpan }`, and `SpanHandle` has no `end`. **Missing; high confidence; high local relevance** for stream instrumentation. [Announcement](https://developers.cloudflare.com/changelog/post/2026-07-28-start-active-span/); [contract](https://developers.cloudflare.com/workers/observability/traces/custom-spans/#tracingstartactivespanname-callback-args); [handle, lines 16–21](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/tracing/span.ts#L16-L21); [namespace, lines 145–150](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/tracing/span.ts#L145-L150)
- **September 25, 2026 — `startSpan`, `getActiveSpan`, `recordException`, `setAttributes`:** Cloudflare added a non-activating manually ended span, active-span lookup, explicit exception recording, and bulk attribute assignment. All are absent from Lopata's public namespace/handle. The internal `startSpan(opts, fn)` at lines 127–129 is an unrelated callback runner, not `tracing.startSpan(name): Span`. **Missing; high confidence; high local relevance.** [Announcement](https://developers.cloudflare.com/changelog/post/2026-09-25-custom-span-apis/); [API reference, updated September 25](https://developers.cloudflare.com/workers/observability/traces/custom-spans/); [internal function and public namespace](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/tracing/span.ts#L127-L150)
- **Current contract — chaining and forwarded arguments:** Cloudflare's `setAttribute` and `setAttributes` return the same span; `enterSpan(name, callback, ...args)` and `startActiveSpan` forward the arguments after the span parameter. Lopata's `setAttribute` returns `undefined`, and `enterSpan` accepts/calls only `(name, fn)`. **Partial; high confidence.** Simple chaining or argument-forwarding code therefore fails even if it uses the old entry method. [Current API reference](https://developers.cloudflare.com/workers/observability/traces/custom-spans/); [setter, lines 70–76](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/tracing/span.ts#L70-L76); [enterSpan, lines 145–146](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/tracing/span.ts#L145-L146)
- **Current contract — lifecycle and root handling:** `end()` is idempotent; after ending, `isTraced` becomes false and annotation calls are ignored. `getActiveSpan()` returns the invocation root if no child is active, and `undefined` outside an invocation; ending the root has no effect. Lopata has an always-true handle field and no public lifecycle controls. **Missing lifecycle semantics; high confidence.** The local runtime's choice to trace every request is distinct from the required ended-span semantics. [Span lifecycle](https://developers.cloudflare.com/workers/observability/traces/custom-spans/#spanend); [active-span lookup](https://developers.cloudflare.com/workers/observability/traces/custom-spans/#tracinggetactivespan); [handle](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/tracing/span.ts#L70-L76)
- **Current contract — data bounds:** names are truncated to 64 bytes; each span accepts approximately 64 KB of attribute and exception data, after which further additions are ignored and warning attributes identify dropped data. The inspected runner stores the supplied name and attributes without these Cloudflare bounds. **Partial; medium-high confidence; lower priority than missing methods.** [Limits](https://developers.cloudflare.com/workers/observability/traces/custom-spans/#data-limits); [span construction/setter](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/tracing/span.ts#L44-L76)
- **Vite module wiring:** `src/vite-plugin/modules-plugin.ts:44–81` emits a `cloudflare:workers` module with classes, env, waitUntil and cache, but no tracing export. The Bun virtual module does export tracing. **Partial across entry paths; high confidence; high local relevance.** The generated module must be considered separately from runtime span implementation. [Vite generated module](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/vite-plugin/modules-plugin.ts#L44-L81); [Bun virtual module](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/virtual-modules.ts#L20-L55); [Cloudflare access paths](https://developers.cloudflare.com/workers/observability/traces/custom-spans/)
- **November 7, 2025 — automatic tracing open beta; May 7, 2026 — DO/Worker subrequest propagation; September 17, 2026 — RPC session/call spans:** these are annual changes, but Lopata already has its own automatic spans, async context and binding instrumentation. They should be classified as **analogous/partial, not wholly absent**; exact Cloudflare span shape and cross-thread propagation were not verified. [Open beta](https://developers.cloudflare.com/changelog/post/2025-11-07-automatic-tracing/); [propagation](https://developers.cloudflare.com/changelog/post/2026-05-07-automatic-tracing-across-do-and-worker-subrequests/); [RPC spans](https://developers.cloudflare.com/changelog/post/2026-09-17-javascript-rpc-session-spans/); [local architecture](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/CLAUDE.md#L102-L104)
- **August 24, 2026 — preserved exception information:** Cloudflare preserves exception details in console output and exposes structured Tail Worker `errorInfo`. Lopata's console capture retains stack text and persists errors, so the basic logging improvement is analogous; no full Tail Worker event contract is established, and Dynamic Worker `tails` is dropped. **Partial.** [Announcement](https://developers.cloudflare.com/changelog/post/2026-08-24-preserve-exception-info/); [console capture](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/plugin.ts#L37-L64); [loader init drops tails](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings/worker-loader.ts#L102-L108)
- **August 4, 2026 — local tracing/Local Explorer:** this is a local development capability, not inherently cloud-only. Lopata's dashboard provides analogous local trace inspection, without implementing Wrangler's explorer interface. [Announcement](https://developers.cloudflare.com/changelog/post/2026-08-04-local-tracing/); [local dashboard and tracing](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/CLAUDE.md#L102-L108)
- **Not missing Cloudflare APIs:** the current custom-span documentation explicitly says `spanContext()` and `setStatus` are not yet available. Do not add them to the compatibility backlog as shipped requirements. [Limitations](https://developers.cloudflare.com/workers/observability/traces/custom-spans/#limitations)

### Inferences

- A coherent compatibility fix would need the public tracing namespace, Span handle/lifecycle contract, and every supported module entry path. Adding only `getActiveSpan()` would leave several common documented examples broken.
- Existing tests exercise synchronous/asynchronous `enterSpan`, nesting, exceptions and a single attribute setter. They do not establish the newer API contract. [Tests](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/tests/tracing-custom-spans.test.ts#L36-L149)

### Gaps

- No trace comparison was performed against Cloudflare's automatic span names, OpenTelemetry schema, sampling behavior, or RPC session span hierarchy.
- Vite's missing named export is source-established; no full Vite application build/import probe was run.

## Which WebSocket and stream changes are missing or already provided natively?

### Takeaway

The custom WebSocket pair misses modern binary delivery and close semantics, with lightweight probes confirming observable mismatches. Several other annual Web API additions are available directly in the tested Bun version and should not be presented as missing. [Pair implementation](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings/websocket-pair.ts); [WebSocket announcement](https://developers.cloudflare.com/changelog/post/2026-04-21-websocket-standard-binary-type/); [compatibility flags](https://developers.cloudflare.com/workers/configuration/compatibility-flags/)

### Cited Findings

- **March 17, 2026 effective / April 21 announcement — standard `binaryType`:** non-hibernating Workers WebSockets implement `binaryType`, defaulting to `'blob'` under the modern flag, with selectable `'arraybuffer'`. DO hibernating handlers continue to receive ArrayBuffer payloads. Lopata's `CFWebSocket` has no implemented `binaryType`, its event data type is only string/ArrayBuffer, and send normalization always produces ArrayBuffer for binary views. **Missing; high confidence; high local relevance.** [Announcement and hibernation exception](https://developers.cloudflare.com/changelog/post/2026-04-21-websocket-standard-binary-type/); [pair fields, lines 11–53](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings/websocket-pair.ts#L11-L53); [binary delivery, lines 95–107](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings/websocket-pair.ts#L95-L107)
- **April 7, 2026 — automatic close replies / `allowHalfOpen`:** the default runtime completes the handshake before delivering the peer close event, so the close handler observes CLOSED. `accept({ allowHalfOpen: true })` permits explicit control and the event observes CLOSING. Lopata's `accept()` takes no options, and it dispatches the peer close event at line 127 before setting peer state CLOSED at line 131. **Partial, missing option and incorrect event-state ordering; high confidence; high local relevance.** [Announcement](https://developers.cloudflare.com/changelog/post/2026-04-07-websocket-auto-reply-to-close/); [accept](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings/websocket-pair.ts#L71-L85); [close](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings/websocket-pair.ts#L111-L140)
- **March 3, 2026 — close reason validation:** `websocket_close_reason_byte_limit` enforces the standard maximum of **123 UTF-8 bytes**, throwing `SyntaxError` DOMException for an oversized reason. Lopata forwards reasons without byte validation. **Missing; high confidence; high local relevance**, including multibyte text. [Compatibility flags](https://developers.cloudflare.com/workers/configuration/compatibility-flags/); [close method](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings/websocket-pair.ts#L111-L140)
- **October 25/31, 2025 — 32 MiB messages:** Cloudflare raised the WebSocket message limit to 32 MiB. Lopata's pair has no message-size enforcement, and the inspected Bun server WebSocket options do not set `maxPayloadLength`. **Unverified network parity / missing explicit pair limit, not a proven 1 MiB implementation limit.** Confidence is high for the source omission, lower for actual network behavior. [Runtime date](https://developers.cloudflare.com/workers/platform/changelog/); [announcement date](https://developers.cloudflare.com/changelog/post/2025-10-31-increased-websocket-message-size-limit/); [pair send](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings/websocket-pair.ts#L87-L108); [server options](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/cli/dev.ts#L440-L470)
- **February 19, 2026 — iterable request/response bodies:** Workers added `fetch_iterable_body` for iterable and async-iterable byte chunks. Native Bun **1.3.14** accepted both tested Response inputs and returned `AB`; Lopata's Response shim delegates the body to the native constructor. **Native-supported for the probed Response cases**, not missing. [Compatibility flags](https://developers.cloudflare.com/workers/configuration/compatibility-flags/); [Response delegation](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/setup-globals.ts#L85-L96)
- **March 17, 2026 — global Performance classes:** the compatibility inventory exposes `PerformanceEntry`, `PerformanceMark`, `PerformanceMeasure`, `PerformanceResourceTiming`, `PerformanceObserver` and `PerformanceObserverEntryList`. All six existed as functions in Bun 1.3.14. **Native-supported availability**, not a missing global API. Lopata separately forces `performance.timeOrigin` to zero. [Compatibility flags](https://developers.cloudflare.com/workers/configuration/compatibility-flags/); [timeOrigin setup](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/setup-globals.ts#L130-L135)
- **March 24, 2026 — stream specification fixes:** the flags inventory includes encoder backpressure with high-water mark zero and writable-writer conformance fixes. Lopata uses native Web streams with specific Cloudflare stream shims; availability is not proof of these exact backpressure/error semantics. **Inventory item requiring targeted native checks**, not a substantiated missing method. [Compatibility flags](https://developers.cloudflare.com/workers/configuration/compatibility-flags/); [stream globals](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/setup-globals.ts#L98-L109)
- **January 15, 2026 — fetch override refinement; March 3 — CJK decoder and unhandled-rejection scheduling fixes:** these are behavior changes rather than new named APIs. Lopata largely delegates the underlying APIs to Bun, so they require focused conformance cases before assigning a missing classification. [Compatibility flags](https://developers.cloudflare.com/workers/configuration/compatibility-flags/); [global setup](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/setup-globals.ts)

### Inferences

- The direct pair probes observed: `binaryType` initially undefined; setting `'blob'` still delivered ArrayBuffer; a peer close listener observed OPEN (`1`); passing `{ allowHalfOpen: true }` made no difference; a 160-byte emoji close reason was accepted. These match the source-established omissions above.
- The behavior owner is the shared pair/event-delivery implementation. Worker-thread and DO WebSocket bridges should be included in eventual verification because they forward pair events; the direct pair probe alone is not a network integration test. [Bridge architecture](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/CLAUDE.md#L45-L60)

### Gaps

- No 32 MiB network-message test was run, and Bun's effective server payload default was not established. Do not claim large network messages fail at a specific size.
- Iterable Request/fetch bodies, cancellation, malformed chunk rejection, PerformanceObserver event behavior, and the March stream fixes were not exhaustively tested.
- Compatibility-date activation and old-date opt-outs need separate config/runtime verification. The native probes establish present behavior only.

## Does the Worker Loader implementation cover Dynamic Workers, Code Mode, and facets?

### Takeaway

Lopata provides simple dynamically loaded fetch and plain-value RPC, but it drops several documented contracts needed by real Dynamic Worker applications. The highest-impact omissions are custom binding transfer/RPC callbacks, outbound interception, entrypoint props/limits, and runtime module/context setup. [Implementation](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings/worker-loader.ts); [Dynamic Worker contract](https://developers.cloudflare.com/dynamic-workers/api-reference/)

### Cited Findings

- **March 24, 2026 — open beta:** Dynamic Workers became open beta for paid accounts. Worker Loader existed before that milestone; do not label the entire binding as invented in March. The announcement documents `load()` as a convenience equivalent to loading without a reusable identity using `get(null, callback)`. **Lopata supports load and lazy named get, but not the documented nullable-ID path.** [Announcement](https://developers.cloudflare.com/changelog/post/2026-03-24-dynamic-workers-open-beta/); [get implementation, lines 250–264](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings/worker-loader.ts#L250-L264)
- **December 19, 2025 — nullable dynamic names:** the runtime changelog records accepting null worker names. Lopata declares `get(id: string)` and passes the ID into filesystem path construction. A null ID would reach a string-only path operation rather than generate an uncached identity. **Missing; high source confidence; medium behavioral confidence without a dedicated probe.** Current API-reference `get` typing still shows string, so cite the dated runtime entry/open-beta announcement for nullable support. [Runtime changelog](https://developers.cloudflare.com/workers/platform/changelog/); [open-beta announcement](https://developers.cloudflare.com/changelog/post/2026-03-24-dynamic-workers-open-beta/); [constructor](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings/worker-loader.ts#L61-L68); [get](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings/worker-loader.ts#L256-L264)
- **Current env contract, documentation updated September 10, 2026:** Dynamic Worker env supports structured-cloneable values and ServiceBindings, including loopbacks with tenant-specific `ctx.props`. Lopata calls `JSON.parse(JSON.stringify(env))`, which loses Maps, ArrayBuffers and callable bindings, and returns `{}` if serialization throws. **Partial; high confidence; high local relevance.** This is a substantive difference from structured-clone transfer, not merely a type declaration mismatch. [API reference](https://developers.cloudflare.com/dynamic-workers/api-reference/); [custom binding examples, updated May 5](https://developers.cloudflare.com/dynamic-workers/usage/bindings/); [sanitizeEnv, lines 280–287](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings/worker-loader.ts#L280-L287)
- **Current RPC transfer contract:** a dynamic worker can invoke arbitrary custom RPC APIs supplied from the parent. Lopata posts argument arrays and return values directly across Bun workers, with no ServiceStub/RpcTarget/function marshalling in this loader path. **Partial; high confidence; high local relevance** for callback APIs and returned capabilities. The loader tests use an unbranded plain class and JSON-like values, not this contract. [Binding contract](https://developers.cloudflare.com/dynamic-workers/usage/bindings/); [caller transfer, lines 192–195](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings/worker-loader.ts#L192-L195); [worker return path](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings/worker-loader-entry.ts#L138-L141); [existing tests](https://github.com/contember/lopata/blob/8b82801ac83d4880d64a0cfa948698347ea84f1a/tests/worker-loader.test.ts#L43-L77)
- **Current `globalOutbound`, egress documentation updated September 29, 2026:** null must deny both fetch and connect; a supplied ServiceStub must intercept/redirect them.
