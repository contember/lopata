# Workers bindings: annual API-change research

## Scope, baseline, and evidence

- **Window:** 2025-10-05 through 2026-10-05, inclusive. Research retrieved on 2026-10-05.
- **Comparison:** [Lopata PR #31](https://github.com/contember/lopata/pull/31), head `8b82801ac83d4880d64a0cfa948698347ea84f1a`, base `99ae836125d56f34d97a007563f7cb4ac21866b5`. All local line references below refer to that head. [Immutable source tree](https://github.com/contember/lopata/tree/8b82801ac83d4880d64a0cfa948698347ea84f1a/src/bindings).
- **Method:** official dated changelogs, official current API documentation, corroborating workerd declarations, binding-owner code, construction paths, and selected existing tests. No implementation changes, test execution, live inference, browser execution, or Docker/Sandbox integration checks.
- **Boundary:** binding/product contracts. Globals/modules and configuration/deployment are adjacent research areas; overlaps are listed at the end.
- **Date rule:** publication/frontmatter dates establish inclusion. A documentation update establishes the current contract, not necessarily its introduction date. An older API mentioned in a new announcement is not automatically a new API.
- **Status:** **missing** = absent method/contract; **partial** = a usable subset with a concrete mismatch; **supported** = matching inspected code, not live certification; **cloud-only** = infrastructure, billing, placement, or hosted-service behavior rather than a local API requirement.
- **Priority:** **P1** = direct application failure, data/replay error, or broad contract incompatibility; **P2** = useful local feature with a narrower audience or larger implementation; **P3** = low immediate local value or account/plan fidelity. Confidence concerns the documented mismatch, not implementation effort.

The existing `CLOUDFLARE-COMPATIBILITY.md` covers approximately April–October 2026. It is not a full-year inventory; its accepted exclusions and implemented PR work must remain distinguishable from newly discovered omissions. Evidence: `CLOUDFLARE-COMPATIBILITY.md`, especially its scope and deferred facets entry at line 97.

## Coordinator summary

### Takeaway

The most practical omissions are **Queue metrics/producer results, DO `deleteAll()` alarm clearing, structured email results and MIME handling, and AI option/input transport**. The largest application-level gaps are **Workflow stream checkpoints and repeated step names, modern Browser binding APIs, DO facets, and the Container primitives required by Sandbox SDK 1.0**. Evidence and dated sources are attached to each finding below.

### Cited Findings

| First follow-up                        | Finding IDs                      | Reason                                                                                                                               |
| -------------------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Small owner-level contract fixes       | DO-1, Q-1, EMAIL-1–3, AI-2       | Wrong observable results, scheduled alarms left behind, MIME corruption, or silently discarded options.                              |
| Workflow execution/checkpoint fidelity | WF-1–3, WF-5                     | Valid loops/large workflows fail; streams do not survive replay; new deletion API is absent.                                         |
| Modern local product surfaces          | IMG-2, BR-1–2, CT-1              | Direct documented calls fail even though older related shims exist.                                                                  |
| Larger follow-up features              | DO-2, CT-2–4, ART-1, AI-5, NEW-3 | Isolated facet databases, runtime container control, repository capabilities, Items, and Stream bindings need explicit product work. |

### Inferences

Priority is an emulator-focused judgment. API shapes, deterministic local persistence, and proxy transport are more useful locally than reproducing global placement, billing, or inference capacity. A new SDK dependency is not evidence that its underlying runtime contract is supported.

### Gaps

This is a broad evidence-backed review, not proof that every announcement was discovered or that every binding passes end-to-end conformance. Several current contracts have no independently established introduction date; they are explicitly separated below.

## 3. Queues: realtime metrics and producer return values

### Takeaway

The April producer contract is missing even though queue state already exists locally. This is a relatively contained, high-value binding-owner change. Evidence: `src/bindings/queue.ts:123–189,401–403,429–490`.

### Cited Findings

**Q-1 — missing; P1; high for absent APIs/results.** [2026-04-28 announcement](https://developers.cloudflare.com/changelog/post/2026-04-28-improved-queues-metrics/) adds `env.QUEUE.metrics()` with `backlogCount`, `backlogBytes`, and `oldestMessageTimestamp`, and metrics on `send`/`sendBatch` responses. The [JavaScript reference, updated 2026-07-06](https://developers.cloudflare.com/queues/configuration/javascript-apis/), specifies the producer result as `{ metadata: { metrics: QueueMetrics } }`. Local `send():123–144` and `sendBatch():146–189` return `Promise<void>` and there is no `metrics()` method. Pull responses contain only messages (`PullResponse:401–403`, implementation 429–490), while the announcement adds `metadata.metrics` to REST pull/send/batch results, using snake-case fields. Worker construction uses a generic RPC proxy (`thread-env.ts:111–113`), but the binding owner has no metric operation to forward.

**Source disagreement:** the dated announcement explicitly uses `oldestMessageTimestamp: Date | undefined`; the current JavaScript reference says `number` milliseconds and omits the empty-queue case. The absence of the API and result envelope is high confidence; the precise timestamp representation must be resolved against shipped runtime types/behavior before implementation. Do not silently choose one as settled.

Free availability and plan-specific retention on [2026-02-04](https://developers.cloudflare.com/changelog/product/queues/) concern cloud plans. New subscription sources, such as Artifacts and Email Sending, concern cloud event delivery rather than a new producer method; the pre-existing event-subscription feature should not be dated as a new annual API merely because new sources appeared.

### Inferences

Local SQLite can supply deterministic metrics without reproducing Cloudflare analytics. Unacknowledged, delayed, and inflight messages should follow the documented backlog definition rather than count only currently visible messages.

### Gaps

No queue behavior was executed, and the timestamp documentation conflict remains open.
